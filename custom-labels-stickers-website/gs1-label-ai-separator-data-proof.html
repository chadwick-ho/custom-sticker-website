How to Proof GS1 Barcode Separators Between Lot and Expiry

The scanner beeps. A long string appears. The receiving application fills the lot field with the lot number and the digits intended for expiry, leaving the date field empty. In this illustrative case, making the barcode larger would leave the central question unanswered. Where did the boundary between the two fields disappear?

For labels using GS1 element strings, ask for a proof that follows approved values from the source record through the encoded data to the fields saved by the receiving application. Confirm the carrier and syntax first. A GS1 DataMatrix carrying element strings and a QR code carrying a web address call for different data checks. DataMatrix and QR scanning workflows

Why a readable caption can hide a boundary error

A GS1 Application Identifier (AI) gives a data field its meaning. AI 10 introduces a batch or lot number and AI 17 introduces an expiration date. In the human-readable interpretation, the parentheses around the AIs help a person recognize them. Those printed parentheses do not supply the encoded boundary between the values. The GS1 General Specifications describe the identifiers, data formats, human-readable interpretation and separator rules. GS1 General Specifications

The lot field has variable length. If a following field starts with the digits 17, a parser needs to know whether those digits are still part of the lot. In this arrangement the lot element string must be terminated with the appropriate separator before the expiration-date element string begins. If the lot is the final field, there is no following field to separate. For other AIs, use the GS1 rules for predefined length. Knowing that a particular value always has the same length in your database is insufficient.

FNC1 has more than one use. In relevant GS1 symbols it can identify the GS1 encoding at the start and can serve as a separator after a non-predefined-length element string. The initial function and an internal field boundary are two distinct things to check. The precise representation depends on the carrier and the scanner interface. GS1 explanation of FNC1

Trace one boundary through three representations

In this conceptual example, a lot is followed by an expiry. It shows just the two fields under review. The actual message must include the identifiers and other data required by your application.

Representation What the reviewer should see
Caption on the label Parenthesized AI 10 with the approved lot, then parenthesized AI 17 with the approved expiry
Inspection of encoded data Lot element string, a separator at its end, then the expiry element string
Record saved by the receiving application The exact lot in the lot field and the corresponding date in the expiry field

Ask the system provider for a diagnostic capture that makes normally invisible separators visible and explains its notation. A tool might display a group separator as GS inside angle brackets. Those visible letters are the tool's representation of a control character. Typing them into the artwork or data file as ordinary text changes what the scanner receives. Compare the capture before and after the scanner's configured output formatting if both are available.

Locate the first disagreement

Work from one known test row. Retain its approved product identity, lot and expiration date alongside the art revision. Decode the generated proof with an appropriate diagnostic tool, then scan a representative printed proof through the actual receiving setup. Save both outputs with their software or configuration references.

If the diagnostic decode already places the boundary incorrectly, send the source row and generator settings to the owner of the encoding template. If the diagnostic decode shows the boundary but the input arriving at the application has lost it, review scanner output formatting and interface handling with the system owner. If the application's input is correct and its saved fields are wrong, review its parser or field mapping. A screenshot of a text box alone leaves several of these possibilities open.

Include another valid test record with a different lot length. A parser configured to split at a fixed character position can appear to work on one lot length by chance. Where a date is reformatted for display, compare the saved calendar date with the approved source as well as checking the encoded field. Use test records authorized by the data owner and keep the association with each proof clear.

Close the data review by recording expected and observed values field by field, the accepted artwork and template revisions, scanner configuration and receiving software. Evaluate symbol print quality separately if the project calls for verification. What a barcode verification report covers

When requesting a printed data proof, supply the carrier, required AIs, a sanitized sample record, expected parse, scanner interface, label dimensions and quantities by batch. Identify which party will approve the saved fields. Discuss a variable-data label proof
