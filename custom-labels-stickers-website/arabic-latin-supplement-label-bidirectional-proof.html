Arabic and Latin Label Text: Check Direction in the Final Proof

When a supplement label mixes Arabic or Hebrew with Latin product IDs, check both the exact source text and the visual reading order in the returned proof. Do not reverse the source string to make one screen look right. Give the designer the language and composition requirements, and have a qualified reader compare the exported proof with the authorized copy at finished size.

This check matters even when the characters survived data import intact. The UTF-8 handoff guide addresses changed characters; here the question is how intact characters are composed into the line that will be printed.

Keep the source sequence and visible order as separate checks

Unicode's bidirectional-text FAQ explains that right-to-left script can contain left-to-right runs, such as Latin text and digits, and that surrounding context affects punctuation placement. An identifier can therefore need a different directional treatment from the paragraph around it. Do not interpret a right-to-left paragraph as an instruction to reverse every digit or mirror the complete design.

Keep the source copy in the sequence supplied by its authorized owner. Ask the designer to use a text-composition workflow appropriate to the script and the intended directional runs. Merely aligning a text box to its right edge does not document how its mixed content is composed.

Adobe's Illustrator guidance describes script-specific composition, shaping and direction support. Its product instructions establish available workflow controls, not the settings of another application's export or the language capability included in an RP quote. Have the actual designer and converter confirm the accepted file route.

Give the reviewer an identified field set

Use the same SKU, market, language and approved-copy revision for the source and proof. Have the reviewer identify the intended relationship between the product name, number, unit and associated punctuation. Keep a Latin SKU or lot identifier in a separately named field so the team can compare its exact character sequence as well as its position in the sentence.

The public diagram uses fictional fields. It supplies no approved Arabic or Hebrew supplement directions, claims or translation. The real reviewer must use the job's actual copy, including its chosen number forms and punctuation.

Review the export that the converter will use

A designer's editable screen is not the final production export. Compare the actual returned PDF or other accepted proof, identify its revision, and print it at the proposed label size. Have the qualified reader inspect the whole line and neighboring lines, then wrap the proof around the intended bottle. Check that a line break or seam has not separated a number or parenthetical expression from its intended item.

The font handoff guide covers the editable master and embedded or outlined text. Outlining can preserve an appearance, including a wrong appearance; it does not supply missing language approval. If a source edit or composition change is needed, return to the controlled master and generate a new proof. Avoid patching individual letter shapes by eye.

For a reorder with an unchanged approved export, retain that identified file and proof. If the text is re-entered, the composition workflow changes or the panel width changes, ask the reviewer which affected checks must be repeated. A source string that still matches does not by itself approve a new visual arrangement.

Quote the print against the approved language proof

For custom supplement labels, prepare the inquiry with the actual container and dieline, quantity by SKU, authorized language-copy references, proposed accepted export and the person who approves language and layout. State any unresolved text-composition question before release. Ask which print and proof scope can be confirmed; translation, market compliance and any special editable-language support need their actual responsible owners.
