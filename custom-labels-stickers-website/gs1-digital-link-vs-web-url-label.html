GS1 Digital Link or a Website QR Code? Decide What the Label Must Carry

Ask two people to scan the proposed label. The first, a shopper, wants the product instructions. The second, a trading partner, wants a product identifier its receiving software can use. Both may see a square QR code. A successful visit to the instructions page answers only the shopper's question. Before approving the print file, find out whether the trading partner needs a GS1 identifier encoded in the address itself.

Choose the address from the scan result you need

For a campaign whose only requirement is to open a web page, an ordinary web URL may be sufficient. Approve the destination, its owner and the experience on the intended phones. If a partner expects a Global Trade Item Number (GTIN) from the scan, ask the partner which syntax and carrier its system accepts. A product number printed elsewhere on the label, or displayed on the page after it opens, can still be missing from the encoded address.

GS1 Digital Link URI syntax specifies how to express GS1 identification keys in a web address. A QR code is one carrier that can hold that address. The same kind of QR symbol can also hold an ordinary URL. In the uncompressed GTIN form, the path includes the numerical identifier for GTIN, 01, and its 14-digit value. Other supported components have defined positions and meanings. Have the data provider validate the complete address against the applicable syntax. GS1 Digital Link URI Syntax, sections 4–6

Here are two conceptual layouts for a proof discussion. The first route consists of a brand domain followed by a page such as “care instructions.” The other consists of an approved domain, the GTIN path component and the GTIN that belongs to the retail unit. The data team can extract the identifier from the second layout even before deciding which web page the shopper will see. Neither layout requires the designer to invent a number.

Give the data owner an approval job

Start the proof with the owner's product record. Match the GTIN to the exact variant, size and packaging level being ordered. A case and an individual sellable unit may have different records. A real, correctly formatted identifier from the wrong row of the catalog can lead to a convincing page for the wrong pack. Have the product owner sign off the association between the physical SKU and the data supplied for printing.

Ask the system provider for the expected decoded address in a copyable form and for the result its parser extracts from that address. Compare the extracted GTIN with the approved reference, including leading zeros in the representation. If a batch or serial qualifier is part of the agreed workflow, include its expected value and intended use in this comparison. For a deeper decision about which records vary across labels, see the guide to shared and item-specific QR data. Static and unique QR label data

A redirect creates a practical trap. Copying the address bar after the product page loads may capture the destination instead of the address that was printed. Save the initial decode before opening it, then record the final destination separately. If the phone reaches the correct instructions but receiving cannot recover the GTIN, route the initial decode to the data provider. If the identifier is correct but the page belongs to another flavor, trace the destination mapping with the web team.

Preserve literal characters inside the supplied batch value

A batch field can contain a character that also has a structural role in a web address. Have the data provider distinguish the original field value from its representation inside the complete URI. The literal slash in a fictional batch value LOT/A, for example, is data; a slash separating path components has a different job.

The GS1 Digital Link URI Syntax 1.7.0 character-set section identifies percent-encoding for reserved literal characters, including the slash. In a component demonstration, LOT/A becomes LOT%2FA. This fragment does not constitute a valid complete Digital Link address and supplies no assigned GTIN.

Do not ask the artwork team to re-encode an already supplied address by eye. A second encoding step can turn the percent sign into %25: LOT%252FA returns LOT%2FA after one percent-decoding step, rather than the intended LOT/A. This is a reproducible string example, not a prediction of every router or GS1 parser.

Ask the system provider to supply three identified fields: the authorized raw batch value, the complete URI to encode and the expected value recovered by its intended parser. Compare the initial decode from the actual printed proof with the supplied URI, and compare the parser's returned batch with the authorized raw value. Preserve the actual punctuation and case required by that source; do not replace a slash with a dash for convenience.

A browser address bar may display or normalize parts of an address, and a redirect may show another address entirely. Keep the initial scanner output and the intended parser result separate from the final destination. Resolve any handling of encoded separators with the actual system provider; do not decode repeatedly until the screen looks plausible.

For the QR-label inquiry, include the provider-approved complete payload, a non-confidential edge-case field sample, target reading system and the person who owns data acceptance. Ask for the printed-proof scope against that payload. Printing and scanning an address does not establish resolver or receiving-system compatibility.

Decide who maintains the link after printing

If the project uses a resolver to direct requests to different resources, identify the operator, default destination, any other link types needed by partners and who can update their mapping. A standards-based URI can be used without a GS1-conformant resolver. Resolver behavior has its own standard and needs its own assessment when it is part of the requirement. GS1-Conformant Resolver Standard

Before approving a run, repeat the agreed scans from a representative label at the intended size and placement. Where checkout use is proposed, obtain the retailer's acceptance conditions and test its workflow. Retain the package revision, decoded data, destination and scan environment together so a change to one can be reviewed intelligently. Retail checkout placement for two barcodes
