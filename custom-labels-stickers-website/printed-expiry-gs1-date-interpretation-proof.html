Printed Expiry and GS1 Dates: Approve the Same Calendar Date

Approve the calendar date first, then check each representation against it. Printed expiry text, a GS1 date element and the receiving system can use different presentations while referring to the same date. They can also look plausible while referring to different days.

For a supplement brand, this is a data-release question before it is a print-quality question. A sharp expiry field is of little help if the artwork team meant 8 March and the coding template interpreted 3 August. Keep an authorized date reference beside the artwork and the encoded-data proof rather than asking the printer to infer the convention.

Separate the date's meaning from its presentation

Ask the brand's data or quality owner to identify the SKU, lot, date type and intended calendar date. Expiration and best-before are not interchangeable labels for an unspecified date. The owner must select the required meaning and approve the corresponding copy and system field; the printer does not establish shelf life.

GS1 Sweden's Application Identifier guide lists AI 15 for best-before and AI 17 for expiry, with dates expressed as YYMMDD. In addition, GS1's date-convention explanation distinguishes the barcode and its human-readable interpretation from other dates printed on a label, which may be subject to other format requirements. Use the applicable market and product rules for the consumer copy.

Do not replace the human-readable interpretation of a GS1 element with a decorative date string. A separately printed EXP field is a different artwork element and needs its own approved presentation. Identify both on the proof when both exist.

Work one example through the whole handoff

Consider a fictional authorized expiry of 8 March 2027. The examples below show a comparison, not a prescribed consumer-label format or a complete GS1 barcode message.

Representation Demonstration value What the reviewer confirms
Authorized calendar date 8 March 2027 This is the date and date type approved for the named SKU and lot
Separate consumer-facing text EXP 08 MAR 2027 The exact wording and format are approved for the pack and market
GS1 AI 17 data 270308 The date is encoded as year, month, day for the intended expiry element
HRI for that element (17)270308 The visible interpretation corresponds to the encoded element
Receiving record The same calendar date in the system's display format The application parsed and stored 8 March, not 3 August

The string 03/08/27 is a useful ambiguity challenge: different conventions can read it as 8 March or 3 August. Both are real dates, so a validity check alone would not find the disagreement. Retain the convention explicitly rather than correcting one display by eye.

If the source gives only a month or omits a day, return the unresolved input to its owner. Do not invent a first day, last day or default to fill an encoded field. Have the data owner resolve the applicable rules before producing the final values.

Check the generated asset and the actual receiving setup

Have the code owner generate a proof from the controlled source row and retain the generator or template reference. Inspect the date element in the decoded data. Then have the receiving-system owner scan an identified representative printed sample through the intended setup and compare the saved date with the authorized source.

Keep the complete approved message in production even when the review focuses on one date element. For a lot followed by expiry, the GS1 separator guide covers the separate boundary question. Correct separators do not establish that the six date digits represent the intended day.

Record which software or template performs each conversion. A spreadsheet export, an import rule and a label template may all touch the value. If the first disagreement appears in an export, send it to that file owner; if it appears only after scanning, involve the receiving-system owner. Do not compensate for a parser error by printing a different date.

Release the copy and the data together

Retain the source row, authorized date type and calendar date, approved text format, encoded proof, print sample and receiving record under one job reference. Include an ambiguous numeric example in the agreed trial if it can expose a convention mismatch. Keep demonstration data separate from saleable stock.

If the consumer date text gets longer, return its space and legibility to the batch and expiry printing review. If the date or date type changes, return the affected data and copy for approval even when the label's size and colours remain unchanged.

For custom supplement labels, prepare an inquiry on RP's contact page with the actual container, artwork, quantity per design, controlled date examples and the party responsible for later printing. Mark which fields are fixed and which will be added locally. This lets the print discussion protect the approved field while the brand and systems owners retain responsibility for the date itself.
