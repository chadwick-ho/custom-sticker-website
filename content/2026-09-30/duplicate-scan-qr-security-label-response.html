A brand asks for a unique QR code on every holographic seal. That is a reasonable printing request, but it is not yet an authentication workflow. What should happen when the same code is scanned twice? A customer may rescan the same pack, a warehouse worker may check it before shipping, and a copied label may also create repeat scans. Treating all three events as an automatic counterfeit verdict would be an avoidable mistake.

Before ordering variable-code rolls, I would ask the brand to write the response screen and exception path. The code, database, destination domain and customer-service process need to agree. Define the identifier separately from the visit

A serial identifies a specific label or pack when the system is designed to manage it. A scan is an observation about that identifier at a time and place. GS1 explains the distinction between serialization and unique identification. Its digital-signatures standard notes that barcode data can be copied and that conflicting observations may indicate cloned instances. “May” matters: a duplicate scan by itself is not proof of fraud.

Choose whether the public code is static per SKU, unique per pack, or paired with a concealed factor. If a brand wants a true security claim, ask a competent security provider to design the backend and threat model. Do not call an ordinary QR link counterfeit-proof. A visible unique code can still be photographed. The static versus unique guide explains the printing tradeoff; here the decision is how the system responds after printing.

Write three outcomes before approving artwork

First scan: what can the visitor see, and what product details are actually verified? Repeat scan by the same owner: should the page simply note previous activity, or provide a way to confirm ownership? Suspicious scan pattern: what review message appears without accusing the customer or exposing sensitive location data? A calm “We have seen this code before; contact the brand for review” may be safer than a dramatic red “FAKE” banner when the signal is ambiguous.

Document who receives alerts and how a genuine customer can report a problem. If the web service is unavailable, the page should offer a useful fallback rather than a dead link. The brand also needs to decide retention periods, privacy notices and access permissions. GS1's 2D barcode implementation guidance flags web-security and privacy considerations when QR codes lead consumers online.

Make the printed roll match the data file

For variable printing, provide a controlled source file with one identifier per expected label, rules for duplicates and rejected impressions, and the intended URL pattern. Decide whether replacement labels may reuse an ID. Preserve a record of produced, rejected and shipped ranges. If the converter cannot reconcile the physical rolls with the data file, the website may register scans for codes that were never released or fail to recognize legitimately shipped packs.

Check a physical sample from the actual holographic material with the intended phones and scanners. Reflective foil can change camera contrast; keep the QR area and quiet zone readable. Test the first and last labels of a sample roll and compare their serials against the supplied data. The scan-contrast guide focuses on that print detail.

What belongs in a purchasing brief

List carton or product surface, label size, holographic effect, number of unique identifiers, print file owner, website owner, duplicate-scan screen owner, and the person who approves the response wording. Keep printing and software quotes separate. A lower per-label price is not a complete security-system price, and a beautifully printed code does not supply a database.

When you request a custom holographic QR-label quote, send the artwork, code format, sample destination and the desired physical verification method. The brand should be able to answer what the second scan says before the first production roll is released.
